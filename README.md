# Cupertino for Discord

디스코드의 **레이아웃과 색감은 그대로 두고 모양만** 바꾸는 BetterDiscord 테마입니다.
둥근 카드, 얇은 헤어라인, 그리고 **떠 있는 레이어에만** 걸리는 유리(글래스) 효과.

| | |
|---|---|
| **테마** | `Cupertino.theme.css` — 모양 전부 |
| **플러그인** | `dist/CupertinoExtras.plugin.js` — CSS 로 안 되는 것들 |
| **폰트** | `custom.css` — 한글 폰트 (선택) |

---

## 설치

BetterDiscord 가 이미 설치돼 있어야 합니다.

**1. 테마**

`Cupertino.theme.css` 를 테마 폴더에 넣고 설정 → 테마에서 켜세요.

```
%APPDATA%\BetterDiscord\themes\
```

**2. 플러그인** (선택이지만 권장)

`dist/CupertinoExtras.plugin.js` 를 플러그인 폴더에 넣고 켜세요.

```
%APPDATA%\BetterDiscord\plugins\
```

> ⚠️ 테마의 일부 규칙은 플러그인이 붙여주는 `data-cup-*` 속성에 의존합니다.
> 플러그인을 끄면 이미지 확대 뷰어에 모달 유리가 끼는 등 몇 군데가 어긋납니다.
> 자세한 이유는 아래 [성능](#성능-has-를-쓰지-않는-이유) 항목에 있습니다.

**3. 폰트** (선택)

`custom.css` 의 내용을 BetterDiscord 의 **Custom CSS** 창에 붙여넣으세요.

> 디스코드 안정판과 PTB 를 같이 쓴다면 **각각 따로** 넣어야 합니다.
> BetterDiscord 는 데이터를 브랜치별로 보관합니다 (`data/stable/`, `data/ptb/`).

## 기능

### 테마

- **카드 레이아웃** — 사이드바 / 채팅 / 멤버 목록이 각각 둥근 카드로 떨어짐
- **글래스** — 메뉴, 팝오버, 모달, 툴팁, 토스트처럼 **떠 있는 것들**에만
- **헤어라인** — 굵은 구분선 대신 머리카락 굵기의 경계
- **입력 알약** — 메시지 입력창이 알약 모양, 포커스 시 그림자로 반응

넓은 판에는 유리를 걸지 않습니다. 뒤에 정적인 배경밖에 없으면 반투명으로만 보이고
GPU 비용만 듭니다.

### 플러그인

- **폴더 커스텀 아이콘** — 서버 폴더에 macOS 풍 폴더 아이콘 9색 (열림/닫힘)
- **DM 폴더 & 고정** — 개인 DM 을 폴더로 묶고 고정. 목록 위에 바로 바가 생깁니다
- **테마 커스터마이즈** — 라이트/다크, 강조색 9종, 폰트 5종, 글자 크기, 둥글기, 유리 세기
- **커스텀 폼 컨트롤** — 체크박스 / 슬라이더 / 드롭다운을 직접 그림
  (네이티브 `<select>` 는 OS 가 그려서 테마가 닿지 않습니다)
- **"현재 활동 중" 패널 접기**

설정은 BetterDiscord 플러그인 설정에서 열거나, 좌하단에 추가되는 버튼으로 엽니다.

## 성능: `:has()` 를 쓰지 않는 이유

이 저장소에서 가장 값비싸게 배운 것이라 적어 둡니다.

채널이나 DM 을 전환할 때 눈에 띄게 버벅였습니다. 재보니
**테마가 더하는 비용의 94% 가 `:has()`** 였습니다.

| | 전환 4회 기준 |
|---|---|
| 테마가 더하던 비용 | **1805 ms** |
| 그중 `:has()` | **1691 ms** |
| `backdrop-filter` | 365 ms |
| 나머지 | 114 ms |

원인은 인자가 `[class*="..."]` 인 `:has()` 를 브라우저가 인덱싱하지 못한다는 점입니다.
DOM 이 바뀔 때마다 광범위 무효화가 걸리고, **해당하는 요소가 0개여도 비용이 듭니다.**
가장 비싼 형태는 `> *:has([class*="..."])` — 전체 선택자와 자손 `:has` 의 조합이라
메시지가 하나 렌더될 때마다 다시 계산됐습니다.

전부 걷어냈습니다. 두 가지 방법으로:

1. **구조로 대체** — 실제 DOM 을 재서 해시 없이 지목
   ```css
   /* 전 */ [class*="content_"]:has(> [class*="sidebar_"])
   /* 후 */ [class*="base__"] > [class*="content__"]
   ```
2. **플러그인이 판정** — 라이트박스·프로필 배너·입력 푸터처럼 구조로 못 잡는 건
   플러그인이 `data-cup-*` 속성을 붙이고 CSS 는 그 속성만 봅니다.
   태깅은 옵저버 콜백에서 **즉시** 실행되므로 깜빡임이 없습니다.

결과는 **전환 1회당 451 ms → 15 ms**. 약 30배입니다.

같이 정리한 것:

- 레이어 옵저버가 변경 내역을 보지도 않고 **16 ms 마다** 전역 `querySelector` +
  `getComputedStyle`(강제 스타일 재계산)을 돌고 있었습니다 → 관련 변경일 때만, 80 ms 로
- `[class*="standardSidebarView"] *` 같은 전역 `*` + 조상 부분일치 선택자 제거
- 창이 백그라운드면 옵저버가 쉬고, 돌아오면 한 번에 따라잡기

### 측정할 때 주의

순차로 재면 **워밍업 드리프트가 신호를 통째로 삼킵니다.** 실제로 이 프로젝트에서
같은 항목을 두 번 다 반대로 결론냈다가 교차 측정으로 뒤집었습니다.
ON / OFF 를 라운드마다 번갈아 재고 **중앙값**을 쓰세요.

## 빌드

플러그인은 폴더 아이콘 18개(9색 × 열림/닫힘)를 **파일 안에 박아 넣기 때문에**
빌드 단계가 있습니다. `file://` 은 Chromium 이 https 페이지에서 원천 차단해서
로컬 이미지를 그냥 참조할 수 없습니다. 그래서 빌드 시점에 SVG 를 base64 data URI 로
바꿔 템플릿의 `/*__ICONS__*/ {}` 자리에 심습니다. 배포물은 `.plugin.js` 한 장입니다.

```powershell
pwsh src/build.ps1            # dist/ 에만 빌드
pwsh src/build.ps1 -Install   # 빌드 후 BetterDiscord 에 바로 설치
```

`dist/` 는 커밋돼 있으니 그냥 쓰실 거면 빌드할 필요 없습니다.
아이콘 색을 바꾸려면 `src/build.ps1` 의 `$palette` 를 고치고 다시 빌드하세요.

수정할 파일은 `src/CupertinoExtras.template.js` 입니다.
`dist/` 는 산출물이므로 직접 고치지 마세요 — 다음 빌드에 덮어써집니다.

## 알려진 제약

- 디스코드의 해시 클래스명(`chat_f75fb0` 같은)에 기대고 있습니다. 부분일치
  (`[class*="chat_"]`)로 완화했지만, 디스코드가 클래스 **이름 자체**를 바꾸면 깨집니다.
- `visual-refresh` UI 기준으로 맞췄습니다.
- 큰 패널 블러는 기본으로 켜져 있습니다. 사양이 낮으면 설정에서
  **"큰 패널도 블러"** 를 끄세요.
- 라이트 모드는 다크 모드만큼 손보지 못했습니다.
